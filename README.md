# Mono Launcher

Десктопный лаунчер для сборок Minecraft, распространяемых в формате `.mrpack` через GitHub Releases.

Отличное решение для авторов сборок и создателей модовых серверов: публикуете сборку на GitHub — и у игроков она появляется в один клик, с новостями, скриншотами, серверами, баг-репортами в ваши Issues и автоматическими обновлениями. Своя аудитория без магазинов и платформ в середине.

## Возможности
- **Несколько сборок** — каждая со своей вкладкой: релизы с ченджлогами, файлы (моды/ресурспаки/шейдеры/миры) с включением-выключением и поиском, консоль игры.
- **Контент из репозитория сборки**: вкладки «Скриншоты» (локальная папка игрока) и «Сервера» (`servers.json` + свои из `servers.dat`), звёзды и соцсети (`socials.json`) в шапке — кнопками с цветом автора (`color` в `socials.json`), статусы серверов с онлайном («12/100» + никнеймы в подсказке), «Играть на сервере», баннер сборки (`banner.png`), тема лаунчера под стиль сборки (`theme.json` — плавно перекрашивает интерфейс при открытии).
- **Новости**: релизы и дискуссии сборок + релизы самого лаунчера. Обновления лаунчера устанавливаются автоматически (tauri-plugin-updater, релиз подписан minisign).
- **Своя сборка за минуту**: кнопка «Создать сборку» открывает пример, ввод ссылки на репозиторий добавляет сборку в лаунчер (id = `owner-repo`). Ссылка-приглашение (`mono://add-pack?...` или `n1orio.github.io/mono-launcher/?url=...`) добавляет сборку в один клик.
- **Платные сборки через Boosty**: если у сборки задан `boostyBlog`, игрок привязывает свой токен Boosty — подписка на блог издателя открывает скачивание и запуск (проверка через API Boosty, без своего бэкенда, с льготой оффлайн до 3 дней).
- **Каталог сборок**: вкладка «Каталог» — курируемый список сборок с описаниями и тегами (`catalog.json` в репозитории лаунчера), установка из каталога в один клик; авторы предлагают сборку через issue с шаблоном.
- **Минимальная оперативка**: `minRam` в `pack.json` издателя (МБ) — бейдж у сборки, подсказка в настройках и защита от запуска при нехватке ОЗУ.
- **Баг-репорты**: кнопка «Сообщить о баге» открывает форму Issues репозитория сборки с предзаполненным окружением (версия сборки, Minecraft, лаунчер, ОС).
- **Целостность файлов**: все файлы сверяются с sha1/sha512 из `modrinth.index.json`; файлы из недоверенных источников и `.jar` из `overrides` помечаются как кастомные и показываются в предупреждающем баннере.
- **Вход**: оффлайн-аккаунт или Microsoft (device code flow). **Несколько аккаунтов**: список сохранённых профилей в Настройках с переключением в один клик (каждый вход попадает в список и становится активным).
- **Статистика**: пилюля «N ч» в шапке сборки (playtime); у свежеустановленной сборки — «Ещё не запускалась» до первого запуска.
- Тёмная/светлая тема, русский/английский интерфейс, Discord RPC, playtime, автодетект Java 21+ и JRE-каталогов.

## Стек
- **Backend:** Rust + [Tauri 2.0](https://tauri.app)
- **Frontend:** Nuxt 3 (Vue 3 + TypeScript + Tailwind CSS), SSR выключен — SPA поверх IPC
- **Источник сборок:** `.mrpack` из GitHub Releases

## Авторам сборок: публикация и распространение

### Шаг 1. Соберите сборку в `.mrpack`
В Prism Launcher: правый клик по инстансу → **Экспорт** → **Modrinth Pack (.mrpack)**.
Получится файл `modpack.mrpack` — это zip c `modrinth.index.json` (версия Minecraft, модлоадер, список файлов с хэшами). Имя файла может быть любым с расширением `.mrpack`, но рекомендуем `modpack.mrpack`.

### Шаг 2. Создайте публичный GitHub-репозиторий
Лаунчер ходит в GitHub API без авторизации — репозиторий обязан быть **публичным**.
Из имени репозитория получится id сборки `owner-repo`.

### Шаг 3. Опубликуйте релиз с двумя файлами
GitHub → **Releases** → **Create a new release**. Тег = версия сборки (например `1.0.0`), заметки релиза станут ченджлогом в лаунчере. К релизу прикрепите ассеты:

| Файл | Обязательно | Назначение |
|------|:-----------:|------------|
| `modpack.mrpack` | да | сама сборка |
| `pack.json` | да | метаданные: название, платность, минимальная оперативка |

⚠️ Релиз нужно **опубликовать** (кнопка «Publish release»), а не оставить draft — черновики не видны лаунчеру.

Пример `pack.json`:
```json
{ "name": "My Pack", "boostyBlog": "my_blog", "minRam": 8192 }
```
- `name` — название сборки (без него берётся имя репозитория).
- `boostyBlog` — ник блога на Boosty: сборка становится **платной** (см. ниже); нет поля — бесплатная.
- `minRam` — минимальная оперативка в МБ (валидный диапазон 256–65536): бейдж «≥ N ГБ» у сборки и защита от запуска при нехватке ОЗУ.
- Принимаются и snake_case-варианты: `boosty_blog`, `min_ram`.

### Шаг 4. Проверьте добавление
В лаунчере: кнопка **«Добавить сборку»** → вставить URL репозитория (или прямую ссылку на `.mrpack`).
Лаунчер проверит релизы: найдёт `.mrpack` и рядом `pack.json` — если всё верно, сборка появится в списке.

### Шаг 5. Распространяйте
- **Универсальная ссылка-приглашение** — лучший способ (подробности в следующем разделе):
  игрок переходит по ссылке — сборка добавляется в лаунчер в один клик.
- **Каталог**: кнопка «Предложить сборку» (issue с шаблоном) или PR в `catalog.json` этого репозитория — сборка появится во вкладке «Каталог» с описанием, тегами и кнопкой «Добавить».
- **Встроенные сборки** — по договорённости с автором лаунчера: `PACKS` в `src-tauri/src/config.rs`.

### Универсальная ссылка-приглашение (для игроков и рекламы)
Одна ссылка делает всё: у игрока с установленным лаунчером открывается лаунчер и сборка
добавляется в один клик; у игрока без лаунчера — страница с кнопкой «Скачать Mono Launcher».

**Формат ссылки** — два варианта, оба работают одинаково:

```
mono://add-pack?url=<кодированный>&name=<кодированный>&blog=<кодированный>
https://n1orio.github.io/mono-launcher/?url=<кодированный>&name=<кодированный>
```

**Параметры** (значения percent-encoded, т.е. `encodeURIComponent`):

| Параметр | Обязательно | Что передаёт |
|----------|:-----------:|--------------|
| `url` | да | Ссылка на репозиторий сборки: `https://github.com/<owner>/<repo>` |
| `name` | нет | Название сборки (если нет — берётся из `pack.json` или имени репозитория) |
| `blog` | нет | Ник блога на Boosty — сборка добавится **платной** (важнее `pack.json`) |

**Как получить готовую ссылку (проще всего):**
добавьте свою сборку в лаунчер, откройте её вкладку и нажмите
**«Скопировать ссылку-приглашение»** в шапке — лаунчер сам соберёт ссылку
со всеми параметрами (включая `blog=` для платных сборок).

**Как собрать руками** (если лаунчера под рукой нет): закодируйте значения и подставьте в шаблон.
Пример для репозитория `https://github.com/n1orio/mono-pack-example`:

```
https://n1orio.github.io/mono-launcher/?url=https%3A%2F%2Fgithub.com%2Fn1orio%2Fmono-pack-example&name=My%20Pack&blog=my-blog
```

Здесь `https%3A%2F%2F...` — это закодированный `https://...`, `My%20Pack` — `My Pack` (пробел → `%20`).
Второй вариант (схема `mono://`) тоже принимает параметры, но в вебе её лучше не публиковать —
браузер покажет «неизвестный протокол»: веб-версия (`https://n1orio.github.io/mono-launcher/?...`)
сама попробует открыть `mono://`, а если лаунчера нет — предложит скачать.

**Что происходит у игрока:**
1. Установлен лаунчер → открывается приложение, сборка валидируется
   (репозиторий должен существовать, а в его **опубликованных** релизах лежать
   `.mrpack` + `pack.json` — иначе игрок увидит ошибку) и добавляется в список.
2. Лаунчер не установлен → открывается веб-страница-мост с названием сборки,
   кнопкой «Открыть в лаунчере» и ссылкой «Скачать Mono Launcher».

**Где публиковать ссылку:** описание и первый комментарий вашего релиза,
README репозитория, Discord/Telegram-каналы, описание видео и твиттер —
ссылка короткая и не требует объяснений.

### Обновления
Выложили новый релиз с новым `modpack.mrpack` и `pack.json` — лаунчер сам заметит и покажет игрокам кнопку обновления (тег релиза = новая версия, ченджлог — из заметок).

### Дополнительный контент (опционально, в корне репозитория)
- `servers.json` — официальные сервера сборки (вкладка «Сервера»): `[{ "name": "Название", "ip": "play.example.com", "port": 25565, "desc": "Описание" }]`
- `socials.json` — цветные кнопки соцсетей в шапке: объект `{ "Discord": "https://…", "Telegram": "https://…" }` или массив; максимум 8, только https, у каждого можно задать `color: "#rrggbb"`.
- `banner.png` — баннер в шапке вкладки сборки.
- `theme.json` — лаунчер перекрасится под стиль сборки: `{ "bg": "#rrggbb", "panel": "…", "input": "…", "border": "…", "tx": "…", "txStrong": "…", "txMuted": "…", "accent": "…", "accentStrong": "…", "accentHover": "…", "accentDeep": "…" }` — все значения hex `#rrggbb`.

### Чеклист перед публикацией
- [ ] Репозиторий публичный
- [ ] Релиз опубликован (не draft), тег = версия сборки
- [ ] В релизе лежат `modpack.mrpack` и `pack.json`
- [ ] `pack.json` — валидный JSON с полем `name` (рекомендуется)
- [ ] Сборка добавилась в лаунчер по ссылке репозитория

## Каталог сборок
Вкладка «Каталог» показывает курируемый список сборок из `catalog.json` в корне этого
репозитория (обновляется по raw.githubusercontent, без API-квот GitHub). Запись каталога:

```json
{
  "name": "My Pack",
  "url": "https://github.com/my-name/my-pack",
  "description": "Короткое описание…",
  "author": "my-name",
  "tags": ["приключения", "магия"],
  "boostyBlog": "my_blog",
  "minRam": 8192
}
```

- `url` — репозиторий GitHub (или прямая ссылка на `.mrpack`), как при добавлении по ссылке.
- `boostyBlog` — если сборка платная (см. ниже), чтобы подписка создавалась сразу.
- `minRam` — минимальная оперативка в МБ.
- «Добавить» ставит сборку одним кликом; у уже добавленных кнопка меняется на «Открыть».
- Авторы: предложить сборку можно кнопкой «Предложить сборку» (issue с шаблоном)
  или PR-ом в `catalog.json` этого репозитория.

## Платные сборки через Boosty (без своего бэкенда)
Проверка подписки идёт от лица игрока, так что издателю не нужен сервер:

1. У игрока есть личный токен Boosty: Boosty → Настройки → **Приложения** → «Создать приложение» (токен выдаётся сразу).
2. В лаунчере (панель подписки в шапке сборки) игрок вставляет токен — лаунчер проверяет
   подписку на ваш блог через `api.boosty.to` (`user/me` + `user/<id>/subscriptions`).
3. Привязка хранится в `licenses.json` в корне лаунчера; после успешной проверки
   действует **льгота до 3 дней** — сетевая проверка нужна не при каждом запуске.
4. Отписка на Boosty → после следующей проверки доступ закрывается.
5. Сборка из-под вашего `pack.json` и ссылка-приглашение автоматически несут
   `boostyBlog` игрокам — перед публикацией положите его в `pack.json` (или пропишите
   в `packs.json` пользователю: `"boostyBlog": "my_blog"`).

Ограничения: проверка требует сети; Boosty-токен игрока — это его секрет, лаунчер хранит
его только локально (`licenses.json`) и не отправляет никуда, кроме `api.boosty.to`.

## Хранение данных
```
~/.local/share/MonoLauncher/
├── packs/<pack_id>/                # данные отдельной сборки
│   ├── versions/<versionId>/       # игровой профиль конкретной версии
│   │   ├── .mono-installed.json     # маркер установки (versionId, name, sourceTag)
│   │   ├── .mono-index.json         # копия modrinth.index.json
│   │   ├── .mono-custom.json        # кастомные моды (недоверенные источники / overrides)
│   │   └── mods/ config/ overrides # содержимое сборки
│   ├── active.json                 # активная версия
│   └── mrpack-cache/               # скачанный .mrpack
├── libraries/                      # библиотеки Minecraft/модлоадера
└── runtime/                        # встроенная Java (опционально)
```
Пользовательские сборки также регистрируются в `packs.json` в корне лаунчера.

## Как работает установка `.mrpack`
1. Скачивается `modpack.mrpack` с GitHub Releases (выбранный тег).
2. Архив распаковывается во временную папку.
3. Читается `modrinth.index.json`: версия Minecraft, модлоадер, массив `files`.
4. Все файлы из `files` скачиваются параллельно (`tokio` + `reqwest`, лимит 8 соединений)
   с проверкой SHA-1/SHA-512; несовпадение удаляет файл и останавливает установку.
5. `overrides/` копируется в профиль версии; пишется маркер установки и индекс; версия становится активной.

## Безопасность
- Моды считаются доверенными только с CDN Modrinth/CurseForge (`cdn.modrinth.com`,
  `dl.modrinth.com`, `mediafiles.forgecdn.net`).
- Остальные файлы и `.jar` из `overrides` — «кастомные»: записываются в `.mono-custom.json`
  версии и показываются в баннере предупреждения. Установка не блокируется (выбор автора),
  но источник подсвечивается.

## Запуск игры
- NeoForge / Forge / Fabric / Quilt (профиль запуска из установщика модлоадера).
- Java 21+; автопоиск в PATH и типовых каталогах (`jre.rs`) или ручной выбор.
- Wayland при пустом/белом окне: `WEBKIT_DISABLE_COMPOSITING_MODE=1` и
  `WEBKIT_DISABLE_DMABUF_RENDERER=1` выставляются автоматически.
- Headless-отладка UI: `scripts/dev-headless.sh`.
