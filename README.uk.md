# Mono Launcher

_[Українська](README.uk.md) · [Русский](README.ru.md) · [English](README.md) · [Deutsch](README.de.md) · [Беларуская](README.be.md)_

Десктопний лаунчер для збірок Minecraft, які поширюються у форматі `.mrpack` через GitHub Releases. Також доступні ресурси з Modrinth і Curseforge.

Чудове рішення для авторів збірок і творців модових серверів: публікуєте збірку на GitHub — і в гравців вона з'являється в один клік, з новинами, скриншотами, серверами, баг-репортами у ваші Issues та автоматичними оновленнями. Своя аудиторія без магазинів і платформ посередині.

## Чому публікувати збірку саме в цьому лаунчері
- **Одне посилання — збірка й лаунчер.** Універсальне посилання-запрошення робить усе за гравця: лаунчер уже є — збірка додається та завантажується одразу; лаунчера немає — сторінка-міст пропонує «Завантажити Mono Launcher», і після встановлення збірка додається так само автоматично. Жодних «завантажте мод, покладіть у папку, налаштуйте».
- **Соцмережі та сервери просто в лаунчері.** `socials.json` виводить кнопки вашого Discord/Telegram у шапку збірки, `servers.json` — офіційні сервери з онлайн-статусом і кнопкою «Грати на сервері» в один клік.
- **Колірна схема під ваш бренд.** `theme.json` плавно перефарбовує весь інтерфейс лаунчера в кольори збірки — у гравця ваш стиль з першого екрана.
- **Новини й оновлення в стрічці гравця.** Релізи та пости Discussions збірки потрапляють просто в стрічку новин лаунчера; нову версію гравець бачить одразу й оновлює в один клік.
- **Баг-репорти з готовим середовищем.** Кнопка «Повідомити про баг» відкриває Issues із заповненим середовищем (версія збірки, Minecraft, лаунчер, ОС) — менше уточнювальних запитань, швидші фікси.
- **Довіра та цілісність.** Усі файли звіряються за хешами з `modrinth.index.json`; вбудовано встановлення модів з Modrinth/CurseForge; є статистика гри та Discord RPC.
- **Публічно та без посередників.** Публікація йде через ваш GitHub Releases — без магазинів і платформ посередині.

## Можливості
- **Кілька збірок** — кожна зі своєю вкладкою: релізи з чейнджлогами, файли (моди/ресурспаки/шейдери/світи) з увімкненням-вимкненням і пошуком, консоль гри.
- **Контент із репозиторію збірки**: вкладки «Скриншоти» (локальна папка гравця) і «Сервери» (`servers.json` + свої з `servers.dat`), зірки та соцмережі (`socials.json`) у шапці — кнопками з кольором автора (`color` у `socials.json`), статуси серверів із онлайном («12/100» + нікнейми в підказці), «Грати на сервері», банер збірки (`banner.png`), тема лаунчера під стиль збірки (`theme.json` — плавно перефарбовує інтерфейс під час відкриття).
- **Новини**: релізи та дискусії збірок + релізи самого лаунчера. Оновлення лаунчера встановлюються автоматично (tauri-plugin-updater, реліз підписано minisign).
- **Своя збірка за хвилину**: кнопка «Створити збірку» відкриває приклад, вставлення посилання на репозиторій додає збірку в лаунчер (id = `owner-repo`). Посилання-запрошення (`mono://add-pack?...` або `n1orio.github.io/mono-launcher/?url=...`) додає збірку в один клік.
- **Платні збірки через Boosty**: якщо у збірки задано `boostyBlog`, гравець прив'язує свій токен Boosty — підписка на блог видавця відкриває завантаження та запуск (перевірка через API Boosty, без власного бекенду, з офлайн-пільгою до 3 днів).
- **Каталог збірок**: вкладка «Каталог» — курований список збірок з описами та тегами (`catalog.json` у репозиторії лаунчера), встановлення з каталогу в один клік; автори пропонують збірку через issue з шаблоном.
- **Мінімальна оперативна пам'ять**: `minRam` у `pack.json` видавця (МБ) — бейдж у збірки, підказка в налаштуваннях і захист від запуску при нестачі ОЗП.
- **Баг-репорти**: кнопка «Повідомити про баг» відкриває форму Issues репозиторію збірки із заповненим середовищем (версія збірки, Minecraft, лаунчер, ОС).
- **Цілісність файлів**: усі файли звіряються з sha1/sha512 з `modrinth.index.json`; файли з недовірених джерел і `.jar` з `overrides` позначаються як кастомні та показуються в попереджувальному банері.
- **Вхід**: офлайн-акаунт або Microsoft (device code flow). **Кілька акаунтів**: список збережених профілів у Налаштуваннях із перемиканням в один клік (кожен вхід потрапляє в список і стає активним).
- **Статистика**: пілюля «N год» у шапці збірки (playtime); у щойно встановленої збірки — «Ще не запускалась» до першого запуску.
- Темна/світла тема, український/російський інтерфейс, Discord RPC, playtime, автодетект Java 21+ і каталогів JRE.

## Стек
- **Backend:** Rust + [Tauri 2.0](https://tauri.app)
- **Frontend:** Nuxt 3 (Vue 3 + TypeScript + Tailwind CSS), SSR вимкнено — SPA поверх IPC
- **Джерело збірок:** `.mrpack` з GitHub Releases

## Авторам збірок: публікація та поширення

### Крок 1. Зберіть збірку у `.mrpack`
У Prism Launcher: правий клік по інстансу → **Експорт** → **Modrinth Pack (.mrpack)**.
Отримаєте файл `modpack.mrpack` — це zip з `modrinth.index.json` (версія Minecraft, модлоадер, список файлів із хешами). Ім'я файлу може бути будь-яким із розширенням `.mrpack`, але рекомендуємо `modpack.mrpack`.

### Крок 2. Створіть публічний GitHub-репозиторій
Лаунчер ходить у GitHub API без авторизації — репозиторій зобов'язаний бути **публічним**.
З імені репозиторію вийде id збірки `owner-repo`.

### Крок 3. Опублікуйте реліз із двома файлами
GitHub → **Releases** → **Create a new release**. Тег = версія збірки (наприклад `1.0.0`), нотатки релізу стануть чейнджлогом у лаунчері. До релізу прикріпіть асети:

| Файл | Обов'язково | Призначення |
|------|:-----------:|-------------|
| `modpack.mrpack` | так | сама збірка |
| `pack.json` | так | метадані: назва, платність, мінімальна оперативна пам'ять |

⚠️ Реліз потрібно **опублікувати** (кнопка «Publish release»), а не залишити draft — чернетки не видно лаунчеру.

Приклад `pack.json`:
```json
{ "name": "My Pack", "boostyBlog": "my_blog", "minRam": 8192 }
```
- `name` — назва збірки (без нього береться назва репозиторію).
- `boostyBlog` — нік блогу на Boosty: збірка стає **платною** (див. нижче); немає поля — безкоштовна.
- `minRam` — мінімальна оперативна пам'ять у МБ (валідний діапазон 256–65536): бейдж «≥ N ГБ» у збірки і захист від запуску при нестачі ОЗП.
- Приймаються і snake_case-варіанти: `boosty_blog`, `min_ram`.

### Крок 4. Перевірте додавання
У лаунчері: кнопка **«Додати збірку»** → вставити URL-адресу репозиторію (або пряме посилання на `.mrpack`).
Лаунчер перевірить релізи: знайде `.mrpack` і поруч `pack.json` — якщо все правильно, збірка з'явиться в списку.

### Крок 5. Поширюйте
- **Універсальне посилання-запрошення** — найкращий спосіб (деталі в наступному розділі):
  гравець переходить за посиланням — збірка додається в лаунчер в один клік.
- **Каталог**: кнопка «Запропонувати збірку» (issue з шаблоном) або PR у `catalog.json` цього репозиторію — збірка з'явиться у вкладці «Каталог» з описом, тегами та кнопкою «Додати».
- **Вбудовані збірки** — за домовленістю з автором лаунчера: `PACKS` у `src-tauri/src/config.rs`.

### Універсальне посилання-запрошення (для гравців та реклами)
Одне посилання робить усе: у гравця зі встановленим лаунчером відкривається лаунчер і збірка
додається в один клік; у гравця без лаунчера — сторінка з кнопкою «Завантажити Mono Launcher».

**Формат посилання** — два варіанти, обидва працюють однаково:

```
mono://add-pack?url=<закодоване>&name=<закодоване>&blog=<закодоване>
https://n1orio.github.io/mono-launcher/?url=<закодоване>&name=<закодоване>
```

**Параметри** (значення percent-encoded, тобто `encodeURIComponent`):

| Параметр | Обов'язково | Що передає |
|----------|:-----------:|------------|
| `url` | так | Посилання на репозиторій збірки: `https://github.com/<owner>/<repo>` |
| `name` | ні | Назва збірки (немає — береться з `pack.json` або назви репозиторію) |
| `blog` | ні | Нік блогу на Boosty — збірка додасться **платною** (важливіше за `pack.json`) |

**Як отримати готове посилання (найпростіше):**
додайте свою збірку в лаунчер, відкрийте її вкладку та натисніть
**«Скопіювати посилання-запрошення»** у шапці — лаунчер сам збере посилання
з усіма параметрами (включно з `blog=` для платних збірок).

**Як зібрати руками** (якщо лаунчера немає поруч): закодуйте значення та підставте в шаблон.
Приклад для репозиторію `https://github.com/n1orio/mono-pack-example`:

```
https://n1orio.github.io/mono-launcher/?url=https%3A%2F%2Fgithub.com%2Fn1orio%2Fmono-pack-example&name=My%20Pack&blog=my-blog
```

Тут `https%3A%2F%2F...` — це закодований `https://...`, а `My%20Pack` — `My Pack` (пробіл → `%20`).
Другий варіант (схема `mono://`) теж приймає параметри, але в вебі його краще не публікувати —
браузер покаже «невідомий протокол»: веб-версія (`https://n1orio.github.io/mono-launcher/?...`)
сама спробує відкрити `mono://`, а якщо лаунчера немає — запропонує завантаження.

**Що відбувається у гравця:**
1. Встановлений лаунчер → відкривається застосунок, збірка валідується
   (репозиторій має існувати, а в його **опублікованих** релізах лежати
   `.mrpack` + `pack.json` — інакше гравець побачить помилку) і додається до списку.
2. Лаунчер не встановлено → відкривається веб-сторінка-міст із назвою збірки,
   кнопкою «Відкрити в лаунчері» та посиланням «Завантажити Mono Launcher».

**Де публікувати посилання:** опис і перший коментар вашого релізу,
README репозиторію, Discord/Telegram-канали, опис відео та твіттер —
посилання коротке та не потребує пояснень.

### Оновлення
Виклали новий реліз з новим `modpack.mrpack` і `pack.json` — лаунчер сам помітить і покаже гравцям кнопку оновлення (тег релізу = нова версія, чейнджлог — із нотаток).

### Додатковий контент (опційно, у корені репозиторію)
- `servers.json` — офіційні сервери збірки (вкладка «Сервери»): `[{ "name": "Назва", "ip": "play.example.com", "port": 25565, "desc": "Опис" }]`
- `socials.json` — кольорові кнопки соцмереж у шапці: об'єкт `{ "Discord": "https://…", "Telegram": "https://…" }` або масив; максимум 8, лише https, у кожного можна задати `color: "#rrggbb"`.
- `banner.png` — банер у шапці вкладки збірки.
- `theme.json` — лаунчер перефарбується під стиль збірки: `{ "bg": "#rrggbb", "panel": "…", "input": "…", "border": "…", "tx": "…", "txStrong": "…", "txMuted": "…", "accent": "…", "accentStrong": "…", "accentHover": "…", "accentDeep": "…" }` — усі значення hex `#rrggbb`.

### Чекліст перед публікацією
- [ ] Репозиторій публічний
- [ ] Реліз опублікований (не draft), тег = версія збірки
- [ ] У релізі лежать `modpack.mrpack` і `pack.json`
- [ ] `pack.json` — валідний JSON із полем `name` (рекомендується)
- [ ] Збірка додалася в лаунчер за посиланням репозиторію

## Каталог збірок
Вкладка «Каталог» показує курований список збірок із `catalog.json` у корені цього
репозиторію (оновлюється по raw.githubusercontent, без API-квот GitHub). Запис каталогу:

```json
{
  "name": "My Pack",
  "url": "https://github.com/my-name/my-pack",
  "description": "Короткий опис…",
  "author": "my-name",
  "tags": ["пригоди", "магія"],
  "boostyBlog": "my_blog",
  "minRam": 8192
}
```

- `url` — репозиторій GitHub (або пряме посилання на `.mrpack`), як під час додавання за посиланням.
- `boostyBlog` — якщо збірка платна (див. нижче), щоб підписка створювалась одразу.
- `minRam` — мінімальна оперативна пам'ять у МБ.
- «Додати» ставить збірку в один клік; у вже доданих кнопка змінюється на «Відкрити».
- Автори: запропонувати збірку можна кнопкою «Запропонувати збірку» (issue з шаблоном)
  або PR-ом у `catalog.json` цього репозиторію.

## Платні збірки через Boosty (без власного бекенду)
Перевірка підписки йде від імені гравця, тож видавцеві не потрібен сервер:

1. У гравця є особистий токен Boosty: Boosty → Налаштування → **Застосунки** → «Створити застосунок» (токен видається одразу).
2. У лаунчері (панель підписки в шапці збірки) гравець вставляє токен — лаунчер перевіряє
   підписку на ваш блог через `api.boosty.to` (`user/me` + `user/<id>/subscriptions`).
3. Прив'язка зберігається в `licenses.json` у корені лаунчера; після успішної перевірки
   діє **пільга до 3 днів** — мережева перевірка не потрібна при кожному запуску.
4. Відписка на Boosty → після наступної перевірки доступ закривається.
5. Збірка з-під вашого `pack.json` і посилання-запрошення автоматично несуть
   `boostyBlog` гравцям — перед публікацією покладіть його в `pack.json` (або пропишіть
   у `packs.json` користувачу: `"boostyBlog": "my_blog"`).

Обмеження: перевірка потребує мережі; Boosty-токен гравця — це його секрет, лаунчер зберігає
його лише локально (`licenses.json`) і не надсилає нікуди, крім `api.boosty.to`.

## Зберігання даних
```
~/.local/share/MonoLauncher/
├── packs/<pack_id>/                # дані окремої збірки
│   ├── versions/<versionId>/       # ігровий профіль конкретної версії
│   │   ├── .mono-installed.json     # маркер встановлення (versionId, name, sourceTag)
│   │   ├── .mono-index.json         # копія modrinth.index.json
│   │   ├── .mono-custom.json        # кастомні моди (недовірені джерела / overrides)
│   │   └── mods/ config/ overrides # вміст збірки
│   ├── active.json                 # активна версія
│   └── mrpack-cache/               # завантажений .mrpack
├── libraries/                      # бібліотеки Minecraft/модлоадера
└── runtime/                        # вбудована Java (опційно)
```
Користувацькі збірки також реєструються в `packs.json` у корені лаунчера.

## Як працює встановлення `.mrpack`
1. Завантажується `modpack.mrpack` з GitHub Releases (вибраний тег).
2. Архів розпаковується в тимчасову папку.
3. Читається `modrinth.index.json`: версія Minecraft, модлоадер, масив `files`.
4. Усі файли з `files` завантажуються паралельно (`tokio` + `reqwest`, ліміт 8 з'єднань)
   з перевіркою SHA-1/SHA-512; незбіг видаляє файл і зупиняє встановлення.
5. `overrides/` копіюється в профіль версії; пишеться маркер встановлення та індекс; версія стає активною.

## Безпека
- Моди вважаються довіреними лише з CDN Modrinth/CurseForge (`cdn.modrinth.com`,
  `dl.modrinth.com`, `mediafiles.forgecdn.net`).
- Інші файли та `.jar` з `overrides` — «кастомні»: записуються в `.mono-custom.json`
  версії та показуються в банері попередження. Встановлення не блокується (вибір автора),
  але джерело підсвічується.

## Запуск гри
- NeoForge / Forge / Fabric / Quilt (профіль запуску з інсталятора модлоадера).
- Java 21+; автопошук у PATH і типових каталогах (`jre.rs`) або ручний вибір.
- Wayland при порожньому/білому вікні: `WEBKIT_DISABLE_COMPOSITING_MODE=1` і
  `WEBKIT_DISABLE_DMABUF_RENDERER=1` виставляються автоматично.
- Headless-налагодження UI: `scripts/dev-headless.sh`.
