# Mono Launcher

_[Беларуская](README.be.md) · [Русский](README.md) · [English](README.en.md) · [Українська](README.uk.md) · [Deutsch](README.de.md)_

Дэсктопны лаўнчар для зборак Minecraft, якія распаўсюджваюцца ў фармаце `.mrpack` праз GitHub Releases. Таксама даступныя рэсурсы з Modrinth і CurseForge.

Выдатнае рашэнне для аўтараў зборак і стваральнікаў модавых сервераў: публікуеце зборку на GitHub — і ў гульцоў яна з'яўляецца ў адзін клік, з навінамі, скрыншотамі, серверамі, баг-рэпортамі ў вашы Issues і аўтаматычнымі абнаўленнямі. Свая аўдыторыя без крамаў і платформаў пасярэдзіне.

## Чаму публікаваць зборку менавіта ў гэтым лаўнчары
- **Адно спасылка — зборка і лаўнчар.** Універсальнае спасылка-запрашэнне робіць усё за гульца: лаўнчар ужо ёсць — зборка дадаецца і спампоўваецца адразу; лаўнчара няма — старонка-мост прапануе «Спампаваць Mono Launcher», і пасля ўстаноўкі зборка дадаецца таксама аўтаматычна. Ніякіх «спампавайце мод, пакладзеце ў папку, наладзьце».
- **Сацсеткі і серверы проста ў лаўнчары.** `socials.json` выводзіць кнопкі вашага Discord/Telegram у шапку зборкі, `servers.json` — афіцыйныя серверы з онлайн-статусам і кнопкай «Гуляць на серверы» ў адзін клік.
- **Колеравая схема пад ваш брэнд.** `theme.json` плаўна перафарбоўвае ўвесь інтэрфейс лаўнчара ў колеры зборкі — у гульца ваш стыль з першага экрана.
- **Навіны і абнаўленні ў стужцы гульца.** Рэлізы і пасты Discussions зборкі трапляюць прама ў стужку навін лаўнчара; новую версію гулец бачыць адразу і абнаўляе ў адзін клік.
- **Баг-рэпарты з гатовым асяроддзем.** Кнопка «Паведаміць пра баг» адкрывае Issues з запоўненым асяроддзем (версія зборкі, Minecraft, лаўнчар, ОС) — менш удакладняльных пытанняў, хутчэйшыя фіксы.
- **Давер і цэласнасць.** Усе файлы звяраюцца па хэшах з `modrinth.index.json`; убудавана ўстаноўка модаў з Modrinth/CurseForge; ёсць статыстыка гульні і Discord RPC.
- **Публічна і без пасрэднікаў.** Публікацыя ідзе праз ваш GitHub Releases — без крамаў і платформаў пасярэдзіне.

## Магчымасці
- **Некалькі зборак** — кожная са сваёй укладкай: рэлізы з чэнджлогамі, файлы (моды/рэсурспакі/шэйдеры/светы) з уключэннем-выключэннем і пошукам, кансоль гульні.
- **Кантэнт з рэпазіторыя зборкі**: укладкі «Скрыншоты» (лакальная папка гульца) і «Серверы» (`servers.json` + свае з `servers.dat`), зоркі і сацсеткі (`socials.json`) у шапцы — кнопкамі з колерам аўтара (`color` у `socials.json`), статусы сервераў з онлайнам («12/100» + нікнеймы ў падказцы), «Гуляць на серверы», банер зборкі (`banner.png`), тэма лаўнчара пад стыль зборкі (`theme.json` — плаўна перафарбоўвае інтэрфейс пры адкрыцці).
- **Навіны**: рэлізы і дыскусіі зборак + рэлізы самога лаўнчара. Абнаўленні лаўнчара ўсталёўваюцца аўтаматычна (tauri-plugin-updater, рэліз падпісаны minisign).
- **Свая зборка за хвіліну**: кнопка «Стварыць зборку» адкрывае прыклад, устаўка спасылкі на рэпазіторый дадае зборку ў лаўнчар (id = `owner-repo`). Спасылка-запрашэнне (`mono://add-pack?...` ці `n1orio.github.io/mono-launcher/?url=...`) дадае зборку ў адзін клік.
- **Платныя зборкі праз Boosty**: калі ў зборкі зададзены `boostyBlog`, гулец прывязвае свой токен Boosty — падпіска на блог выдаўца адкрывае спампоўку і запуск (праверка праз API Boosty, без уласнага бэкенду, з афлайн-ільготай да 3 дзён).
- **Каталог зборак**: укладка «Каталог» — курыруемы спіс зборак з апісаннямі і тэгамі (`catalog.json` у рэпазіторыі лаўнчара), устаноўка з каталога ў адзін клік; аўтары прапануюць зборку праз issue з шаблонам.
- **Мінімальная аператыўная памяць**: `minRam` у `pack.json` выдаўца (МБ) — бейдж у зборкі, падказка ў наладах і абарона ад запуску пры недахопе АЗП.
- **Баг-рэпорты**: кнопка «Паведаміць пра баг» адкрывае форму Issues рэпазіторыя зборкі з запоўненым асяроддзем (версія зборкі, Minecraft, лаўнчар, АС).
- **Цэласнасць файлаў**: усе файлы звяраюцца з sha1/sha512 з `modrinth.index.json`; файлы з недавераных крыніц і `.jar` з `overrides` пазначаюцца як кастомныя і паказваюцца ў папераджальным банеры.
- **Уваход**: афлайн-акаўнт або Microsoft (device code flow). **Некалькі акаўнтаў**: спіс захаваных профіляў у Наладах з пераключэннем у адзін клік (кожны ўваход трапляе ў спіс і становіцца актыўным).
- **Статыстыка**: пілюля «N г» у шапцы зборкі (playtime); у свежаўсталяванай зборкі — «Яшчэ не запускалася» да першага запуску.
- Цёмная/светлая тэма, рускамоўны/англамоўны інтэрфейс, Discord RPC, playtime, аўтадэтэкт Java 21+ і каталогаў JRE.

## Стек
- **Backend:** Rust + [Tauri 2.0](https://tauri.app)
- **Frontend:** Nuxt 3 (Vue 3 + TypeScript + Tailwind CSS), SSR выключаны — SPA паверх IPC
- **Крыніца зборак:** `.mrpack` з GitHub Releases

## Аўтарам зборак: публікацыя і распаўсюджванне

### Крок 1. Збярыце зборку ў `.mrpack`
У Prism Launcher: правы клік па інстансе → **Экспарт** → **Modrinth Pack (.mrpack)**.
Атрымаеце файл `modpack.mrpack` — гэта zip з `modrinth.index.json` (версія Minecraft, модлоадар, спіс файлаў з хэшамі). Імя файла можа быць любым з пашырэннем `.mrpack`, але рэкамендуем `modpack.mrpack`.

### Крок 2. Стварыце публічны GitHub-рэпазіторый
Лаўнчар ходзіць у GitHub API без аўтарызацыі — рэпазіторый абавязаны быць **публічным**.
З імя рэпазіторыя атрымаецца id зборкі `owner-repo`.

### Крок 3. Апублікуйце рэліз з двума файламі
GitHub → **Releases** → **Create a new release**. Тэг = версія зборкі (напрыклад `1.0.0`), нататкі рэлізу стануць чэнджлогам у лаўнчары. Да рэлізу прымацуйце асеты:

| Файл | Абавязкова | Прызначэнне |
|------|:----------:|-------------|
| `modpack.mrpack` | так | сама зборка |
| `pack.json` | так | метаданыя: назва, платнасць, мінімальная аператыўная памяць |

⚠️ Рэліз трэба **апублікаваць** (кнопка «Publish release»), а не пакінуць draft — чарнавікі не відаць лаўнчару.

Прыклад `pack.json`:
```json
{ "name": "My Pack", "boostyBlog": "my_blog", "minRam": 8192 }
```
- `name` — назва зборкі (без яе бярэцца назва рэпазіторыя).
- `boostyBlog` — нік блога на Boosty: зборка становіцца **платнай** (гл. ніжэй); няма поля — бясплатная.
- `minRam` — мінімальная аператыўная памяць у МБ (валідны дыяпазон 256–65536): бейдж «≥ N ГБ» у зборкі і абарона ад запуску пры недахопе АЗП.
- Прымаюцца і snake_case-варыянты: `boosty_blog`, `min_ram`.

### Крок 4. Праверце даданне
У лаўнчары: кнопка **«Дадаць зборку»** → уставіць URL-адрас рэпазіторыя (або прамую спасылку на `.mrpack`).
Лаўнчар праверыць рэлізы: знойдзе `.mrpack` і побач `pack.json` — калі ўсё правільна, зборка з'явіцца ў спісе.

### Крок 5. Распаўсюджвайце
- **Універсальная спасылка-запрашэнне** — лепшы спосаб (падрабязнасці ў наступным раздзеле):
  гулец пераходзіць па спасылцы — зборка дадаецца ў лаўнчар у адзін клік.
- **Каталог**: кнопка «Прапанаваць зборку» (issue з шаблонам) або PR у `catalog.json` гэтага рэпазіторыя — зборка з'явіцца ва ўкладцы «Каталог» з апісаннем, тэгамі і кнопкай «Дадаць».
- **Убудаваныя зборкі** — па дамоўленасці з аўтарам лаўнчара: `PACKS` у `src-tauri/src/config.rs`.

### Універсальная спасылка-запрашэнне (для гульцоў і рэкламы)
Адна спасылка робіць усё: у гульца з усталяваным лаўнчарам адкрываецца лаўнчар і зборка дадаецца ў адзін клік; у гульца без лаўнчара — старонка з кнопкай «Спампаваць Mono Launcher».

**Фармат спасылкі** — два варыянты, абодва працуюць аднолькава:

```
mono://add-pack?url=<закадаванае>&name=<закадаванае>&blog=<закадаванае>
https://n1orio.github.io/mono-launcher/?url=<закадаванае>&name=<закадаванае>
```

**Параметры** (значэнні percent-encoded, г. зн. `encodeURIComponent`):

| Параметр | Абавязкова | Што перадае |
|----------|:----------:|-------------|
| `url` | так | Спасылка на рэпазіторый зборкі: `https://github.com/<owner>/<repo>` |
| `name` | не | Назва зборкі (няма — бярэцца з `pack.json` або назвы рэпазіторыя) |
| `blog` | не | Нік блога на Boosty — зборка дадасца **платнай** (важней за `pack.json`) |

**Як атрымаць гатовую спасылку (няйпрасцей):**
дадайце сваю зборку ў лаўнчар, адкрыйце яе ўкладку і націсніце
**«Скапіраваць спасылку-запрашэнне»** у шапцы — лаўнчар сам збярэ спасылку
з усімі параметрамі (уключаючы `blog=` для платных зборак).

**Як сабраць рукамі** (калі лаўнчара няма побач): закадуйце значэнні і падстаўце ў шаблон.
Прыклад для рэпазіторыя `https://github.com/n1orio/mono-pack-example`:

```
https://n1orio.github.io/mono-launcher/?url=https%3A%2F%2Fgithub.com%2Fn1orio%2Fmono-pack-example&name=My%20Pack&blog=my-blog
```

Тут `https%3A%2F%2F...` — гэта закадаваны `https://...`, а `My%20Pack` — `My Pack` (прабел → `%20`).
Другі варыянт (схема `mono://`) таксама прымае параметры, але ў вэбе яго лепш не публікаваць —
браўзер пакажа «невядомы пратакол»: вэб-версія (`https://n1orio.github.io/mono-launcher/?...`)
сама паспрабуе адкрыць `mono://`, а калі лаўнчара няма — прапануе спампоўку.

**Што адбываецца ў гульца:**
1. Усталяваны лаўнчар → адкрываецца дадатак, зборка валідуецца
   (рэпазіторый павінен існаваць, а ў яго **апублікаваных** рэлізах ляжаць
   `.mrpack` + `pack.json` — інакш гулец убачыць памылку) і дадаецца да спісу.
2. Лаўнчар не ўсталяваны → адкрываецца вэб-старонка-мост з назвай зборкі,
   кнопкай «Адкрыць у лаўнчары» і спасылкай «Спампаваць Mono Launcher».

**Дзе публікаваць спасылку:** апісанне і першы каментар вашага рэлізу,
README рэпазіторыя, Discord/Telegram-каналы, апісанне відэа і твітар —
спасылка кароткая і не патрабуе тлумачэнняў.

### Абнаўленні
Выклалі новы рэліз з новым `modpack.mrpack` і `pack.json` — лаўнчар сам заўважыць і пакажа гульцам кнопку абнаўлення (тэг рэлізу = новая версія, чэнджлог — з нататак).

### Дадатковы кантэнт (апцыянальна, у корані рэпазіторыя)
- `servers.json` — афіцыйныя серверы зборкі (укладка «Серверы»): `[{ "name": "Назва", "ip": "play.example.com", "port": 25565, "desc": "Апісанне" }]`
- `socials.json` — каляровыя кнопкі сацсетак у шапцы: аб'ект `{ "Discord": "https://…", "Telegram": "https://…" }` або масіў; максімум 8, толькі https, у кожнага можна задаць `color: "#rrggbb"`.
- `banner.png` — банер у шапцы ўкладкі зборкі.
- `theme.json` — лаўнчар перафарбуецца пад стыль зборкі: `{ "bg": "#rrggbb", "panel": "…", "input": "…", "border": "…", "tx": "…", "txStrong": "…", "txMuted": "…", "accent": "…", "accentStrong": "…", "accentHover": "…", "accentDeep": "…" }` — усе значэнні hex `#rrggbb`.

### Чэкліст перад публікацыяй
- [ ] Рэпазіторый публічны
- [ ] Рэліз апублікаваны (не draft), тэг = версія зборкі
- [ ] У рэлізе ляжаць `modpack.mrpack` і `pack.json`
- [ ] `pack.json` — валідны JSON з полем `name` (рэкамендуецца)
- [ ] Зборка дадалася ў лаўнчар па спасылцы рэпазіторыя

## Каталог зборак
Укладка «Каталог» паказвае курыруемы спіс зборак з `catalog.json` у корані гэтага
рэпазіторыя (абнаўляецца па raw.githubusercontent, без API-квот GitHub). Запіс каталога:

```json
{
  "name": "My Pack",
  "url": "https://github.com/my-name/my-pack",
  "description": "Кароткае апісанне…",
  "author": "my-name",
  "tags": ["прыгоды", "магія"],
  "boostyBlog": "my_blog",
  "minRam": 8192
}
```

- `url` — рэпазіторый GitHub (або прамая спасылка на `.mrpack`), як пры даданні па спасылцы.
- `boostyBlog` — калі зборка платная (гл. ніжэй), каб падпіска стваралася адразу.
- `minRam` — мінімальная аператыўная памяць у МБ.
- «Дадаць» ставіць зборку ў адзін клік; у ўжо дададзеных кнопка змяняецца на «Адкрыць».
- Аўтары: прапанаваць зборку можна кнопкай «Прапанаваць зборку» (issue з шаблонам)
  або PR-ам у `catalog.json` гэтага рэпазіторыя.

## Платныя зборкі праз Boosty (без уласнага бэкенду)
Праверка падпіскі ідзе ад імя гульца, таму выдаўцу не патрэбны сервер:

1. У гульца ёсць асабісты токен Boosty: Boosty → Налады → **Прыкладанні** → «Стварыць прыкладанне» (токен выдаецца адразу).
2. У лаўнчары (панэль падпіскі ў шапцы зборкі) гулец устаўляе токен — лаўнчар правярае
   падпіску на ваш блог праз `api.boosty.to` (`user/me` + `user/<id>/subscriptions`).
3. Прывязка захоўваецца ў `licenses.json` у корані лаўнчара; пасля паспяховай праверкі
   дзейнічае **ільгота да 3 дзён** — сеткавая праверка не патрэбна пры кожным запуску.
4. Адпіска на Boosty → пасля наступнай праверкі доступ зачыняецца.
5. Зборка з-пад вашага `pack.json` і спасылка-запрашэнне аўтаматычна нясуць
   `boostyBlog` гульцам — перад публікацыяй пакладзіце яго ў `pack.json` (або прапішыце
   ў `packs.json` карыстальніку: `"boostyBlog": "my_blog"`).

Абмежаванні: праверка патрабуе сеткі; Boosty-токен гульца — гэта яго сакрэт, лаўнчар захоўвае
яго толькі лакальна (`licenses.json`) і не адпраўляе нікуды, акрамя `api.boosty.to`.

## Захоўванне даных
```
~/.local/share/MonoLauncher/
├── packs/<pack_id>/                # даныя асобнай зборкі
│   ├── versions/<versionId>/       # гульнявы профіль пэўнай версіі
│   │   ├── .mono-installed.json     # маркер устаноўкі (versionId, name, sourceTag)
│   │   ├── .mono-index.json         # копія modrinth.index.json
│   │   ├── .mono-custom.json        # кастомныя моды (недавераныя крыніцы / overrides)
│   │   └── mods/ config/ overrides # утрыманне зборкі
│   ├── active.json                 # актыўная версія
│   └── mrpack-cache/               # спампаваны .mrpack
├── libraries/                      # бібліятэкі Minecraft/модлоадара
└── runtime/                        # убудаваная Java (апцыянальна)
```
Карыстальніцкія зборкі таксама рэгіструюцца ў `packs.json` у корані лаўнчара.

## Як працуе ўстаноўка `.mrpack`
1. Спампоўваецца `modpack.mrpack` з GitHub Releases (выбраны тэг).
2. Архіў распакоўваецца ў часовую папку.
3. Чытаецца `modrinth.index.json`: версія Minecraft, модлоадар, масіў `files`.
4. Усе файлы з `files` спампоўваюцца паралельна (`tokio` + `reqwest`, ліміт 8 злучэнняў)
   з праверкай SHA-1/SHA-512; несупадзенне выдаляе файл і спыняе ўстаноўку.
5. `overrides/` капіюецца ў профіль версіі; пішацца маркер устаноўкі і індэкс; версія становіцца актыўнай.

## Бяспека
- Моды лічацца даверанымі толькі з CDN Modrinth/CurseForge (`cdn.modrinth.com`,
  `dl.modrinth.com`, `mediafiles.forgecdn.net`).
- Іншыя файлы і `.jar` з `overrides` — «кастомныя»: запісваюцца ў `.mono-custom.json`
  версіі і паказваюцца ў банеры папярэджання. Устаноўка не блакуецца (выбар аўтара),
  але крыніца падсвятляецца.

## Запуск гульні
- NeoForge / Forge / Fabric / Quilt (профіль запуску з інсталятара модлоадара).
- Java 21+; аўтапошук у PATH і тыповых каталогах (`jre.rs`) або ручны выбар.
- Wayland пры пустым/белым акне: `WEBKIT_DISABLE_COMPOSITING_MODE=1` і
  `WEBKIT_DISABLE_DMABUF_RENDERER=1` выстаўляюцца аўтаматычна.
- Headless-адладка UI: `scripts/dev-headless.sh`.
